# Audit — 5개 영역 전수 스캔 (2026-09-09, 루프 사이클 13 시점)

> 스펙 종료 조건의 전제 산출물: 각 영역의 처리 상태·잔여 리스크·보류 사유를 기록한다.
> 스캔 근거: 세션 전체에서 Source 전 파일·Test·Sandbox·workflow 열독 + TODO/FIXME/ponytail 전수 grep(잔여 마커 1개) + Security 체크리스트 행별 대조.

## 영역별 상태

### 1. 보안 — 처리됨 (잔여: 문서화된 2건)

완료: TCP TLS 옵션(2.1.0, 핸드셰이크 상한 15초·슬롯 회수), RUDP CRC32c 무결성(2.2.0, 프로토콜 처리 전 폐기), 기본 연결 키 시작 경고(2.3.0, 키 미노출), `MaxConnections` 양 스택(TCP 수락 후 즉시 닫기·RUDP 수락 전 슬롯 예약), `FrameTimeout` 슬로로리스 방어, `MaxFrameLength` 양 경로(역직렬화 전 거부), MTU 초과 사전 거부, 수신 미처리 흐름 제어 단절(`FlowControl`), RUDP 클라이언트 역방향 접속 거부, 검증된 옵션 계약(17건 핀), 고갈 공격 회귀 2건, 테스트 인증서 플랫폼 주의(Windows ephemeral 키/Linux EKU) 문서화.

잔여(문서화 완료·미조치 사유 명시):

- **RUDP 기본 평문(DTLS 미설정시)** — 2.5.0으로 옵션 DTLS 1.2 기밀성이 들어왔다([[../05-Decisions/0009-rudp-tls-dtls|ADR 0009]]) — 이 항목의 "실 해결(DTLS급)은 범위 밖" 주장은 해소. 미설정 운용시에는 여전히 평문이므로 완화 유지: `Tls` 옵션 또는 TCP TLS/VPN([[../04-Guides/Security|Security]] ✅행).
- **인증·권한·메시지 레벨 속도 제한** — 설계상 앱 책임(ADR 0006), 체크리스트 고지.

### 2. 데이터 유실·정확성 — 알려진 잔여 없음

완료: 끊김 통지 1회 보장(파이프라인·세션 이중 가드), 송신 직렬화 실패 항목 격리(끊김 아님 — 핀 4건), 역직렬화 실패 폐쇄(fail-closed), peer id 재사용 소유자 확인 회수, EOF/프레임 도중 구분, Dispose 경쟁 하 flush 완료 순서, 수신 잔여 드레인(디스패치 루프 finally).

### 3. 성능 — 처리됨 (잔여: 정량화 미실시)

완료: 제로카피 프레임 슬라이스, 지연 컴팩트(2.2.1, O(N²) 복사 제거 — `CompactionCount` 핀), coalesce 송신 배치, ArrayPool 버퍼·PooledBufferWriter, 호스트당 폴링 스레드 1개.

잔여:

- **마이크로벤치 부재** — 개선 주장(복사 감소 등)이 계약 핀으로만 입증되고 정량 수치는 없음. 선택 과제.
- 폴링 간격 1ms 고정 — 조건부 보류(ponytail 마커, 실측 니즈 시 옵션화).

### 4. 코드 구조 — 처리됨

완료: TCP·RUDP 3분할, LiteNetLib 타입 공개면 은닉, 송신 경로 검증·격리 통합(2.3.0). `MessagePipeline`이 최대 클래스(~600줄)나 응집적 — 추가 분할은 회귀 위험 > 이득(동작 보존 원칙상 보류).

### 5. 기능 — 의무 절차 완료

[[Proposals-Upstream]] P1~P4 기록(DS_RPC 인계). 보류: TCP_IOCP(2026-09-08 사용자 결정 — 니즈·벤치마크 근거 시 재검토), IPC 전송(로드맵 이후).

### 기타

테스트 결정성(네트워크 클래스 순차 컬렉션), `SignalGate` 직접 핀 6건(128테스트), DS_RPC 회귀 77/77. `DisconnectedEventArgs` 직접 핀 미실시 — **사유: 데이터 홀더 2속성**으로 Session 이벤트 경로에서 값 검증이 이미 충분(간접 커버), 직접 핀은 자기검증적(tautological)이라 판단.

## 잔여 리스크 (정직 목록)

1. RUDP 평문(기본값 — DTLS 옵션 존재, 미설정 운용시 완화 문서화).
2. 성능 주장의 정량 근거 부재(벤치마크 없음).
3. 검증 파이프라인의 오래된 결과 재생([[../00-AI/PENDING|PENDING]] — 명시 실행만 신뢰 기준).
4. 실서비스 소크(soak) 부분 완화 — 자동 청urn 소크(폭풍·RST/FIN 혼합·포트 재사용)는 스위트 내장(2026-09-09), 24시간+ 실트래픽 소크는 여전히 미수행.

## 결론

다섯 영역 모두 "처리 가능한 실질 항목"은 소진 상태. 잔여는 ①문서화된 범위 밖(RUDP 기밀성·앱 책임), ②사용자 결정 보류(TCP_IOCP), ③선택 과제(벤치마크), ④운영 데이터 필요(소크). 새 실질 단위의 발현 조건: 사용자 니즈 제기, 상위(DS_RPC) 채안 피드백, 또는 실측 데이터.
